# Ayla Power Monitor v1.4 — Telegram Dashboard

**Єдина точка входу:** `main.py`. Ніякого вебсервера, Mini App, `sendWidget` чи публічного HTTPS. У Telegram надсилаються PNG-картки з inline-кнопками.

## Оновлення поверх v1.3.1

Розпакуй ZIP **у корінь наявного проєкту** із заміною лише файлів із патча. **Не видаляй** `.env`, `data/`, базу SQLite, Telegram-сесії. ZIP не містить `.env`, бази чи незмінених файлів. Якщо ти редагував будь-який файл із патча самостійно, збережи його копію перед заміною.

```powershell
pip install -r requirements.txt
python main.py
```

У PyCharm достатньо натиснути Run на `main.py`. На Windows **реальний heartbeat не створюється** — це лише тест Telegram та відображення накопичених даних. На Raspberry Pi (Linux) `main.py` запускає моніторинг у потоці та Telegram polling в основному потоці.

## Telegram

`/dashboard`, `/today`, `/week`, `/month`, `/history`, `/health`, `/settings`, `/status`, `/yesterday`, `/export`, `/help`. Кнопки: **Сьогодні / 7 днів / Місяць / Історія / Здоров'я Pi / Налаштування / Оновити**. У налаштуваннях є перемикачі **Сповіщення** та **Щоденний звіт**; команди `/notify_on`, `/notify_off`, `/daily_on`, `/daily_off` також працюють.

- **Сьогодні:** шкала з 48 півгодинних сегментів; зелений = є heartbeat, червоний = невідомо, темно-сірий = майбутній час. Статистика поточного дня рахується лише до поточного моменту.
- **7 днів:** 7 окремих часових шкал, праворуч **години й хвилини сигналу / невідомого стану**, без відсотків у підписах.
- **Місяць:** календар, майбутні дні не фарбуються як розриви; день переходу на зимовий/літній час може тривати 25/23 години.
- **Здоров'я Pi:** heartbeat, uptime Linux, NTP, SQLite, вільне місце на диску.
- **Сповіщення:** якщо монітор після відновлення записав розрив у `gaps`, бот надішле його в `TELEGRAM_CHAT_ID`. Фоновий цикл перевіряє нові записи кожні 30 секунд, а після перезапуску повторює невідправлені повідомлення. У SQLite `notified=1` встановлюється **після успішної відправки**.
- **Щоденний звіт:** один PNG-звіт **за попередню добу** після **00:10 за Києвом**. Якщо Pi була вимкнена, бот спробує надіслати вчорашній звіт після наступного запуску; звіти за всі пропущені старі дні автоматично не надсилаються. Стан останньої відправки зберігається в `settings` SQLite. При збої Telegram буде повторна спроба.

Для автоматичних повідомлень у `.env` має бути **`TELEGRAM_CHAT_ID`** (і токен). Доступ до команд обмежений `TELEGRAM_ADMIN_IDS`. Якщо `TELEGRAM_CHAT_ID` порожній, інтерактивний бот працює, але автоматичні повідомлення не надсилаються.

## Запуск на Raspberry Pi через systemd

Старі сервіси v1.0 запускали бот та монітор окремо. **Не запускай їх паралельно з новим `main.py`**, інакше буде два polling-клієнти або дубльований heartbeat.

```bash
sudo systemctl disable --now ayla-power-bot.service ayla-power-monitor.service 2>/dev/null || true
# За потреби заміни User=pi та /home/pi на реального користувача/шлях у файлі сервісу.
sudo cp systemd/ayla-power-monitor.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now ayla-power-monitor.service
sudo journalctl -u ayla-power-monitor.service -f
```

Для коректного часу на Pi має працювати NTP (`timedatectl`). Якщо синхронізація недоступна, монітор очікуватиме на неї, щоб не писати недостовірні часові мітки. Бот при цьому може працювати.

## Межі точності

Це **моніторинг heartbeat, не вимірювання напруги**. Розрив може бути спричинений живленням, перезавантаженням Pi, зависанням процесу, зміною годинника тощо. Час між двома heartbeat не доводить безперервну наявність світла. Відсутні дані — **невідомий стан**, а не підтверджене відключення. Для історичних даних `sessions` та `gaps` збережено; міграція бази не потрібна. Перший heartbeat після старту може з'явитися із затримкою через NTP/завантаження Pi.

**Технічне виправлення:** з'єднання SQLite тепер закриваються після кожного запиту, щоб тривалий процес на Raspberry Pi не накопичував відкриті дескриптори.
